# 轮23：原文需求槽与元素绑定

## 1 用户失败
轮22候选因审查把视觉标签“对话内容”当作口述引文，全局拒绝且无HTML；基线主输入1/1、相关提示4/7，但这次视觉本就正确识别input，不能归因审查。用户需要稳定得到可输入的聊天页面，当前可选声明遗漏和伪造来源仍阻断这一目标。

## 2 原因定位
轮21整段可选声明缺失；轮22改逐视觉text对象后只审核e5，而口述明确输入对应的e6已input，目标需求没有作为独立待绑定对象出现。返回的负判引文复制了视觉标签，不在口述原文。视对象为主的审查和自由编写引文把来源混淆引入契约。本轮不删除这次失败，也不在旧响应上放宽校验补出页面。

## 3 假设与目标后的研究复读
通过代码从原口述中提取包含明确文字编辑表述的完整句子，给出稳定原文槽号和字符起止位置，模型只能为每个原文槽选择已知元素ID或明确未决，代码按槽号取回原话，能够消除模型自由生成引文这类失败，并让明确输入要求得到显式绑定或未决报告。

目标提出后复读《链路诊断与Agent架构调研》、[OmniParser §3](https://arxiv.org/html/2408.00203v1)的局部语义职责与对象编号选择，以及[SketchGPT UIST2025](https://orca.cardiff.ac.uk/id/eprint/181362/)的语义/时间关联。采用“受限来源选择”的工程适配，不复现其训练方法，也不将截图任务成绩套到纸面草图；时间对齐暂不实现，因为时间证据尚未核实。本轮只解决明确文字编辑句子的来源与绑定，不宣称提取全部口述需求。

## 4 固定方案与指标
句子按中英文句号/问叹号和换行分割，保留原始字符偏移；仅使用原输入编译器已有的通用编辑行为表达式筛选，不写002标签答案。包含否定/只读或超过400字符的句子标为本地未决，不截短造成语义改变；不将其当可编辑证据。模型返回bindings，每个可用原文槽恰一项requirement_id、vision_id（或null）；不接受任何新引文、文字、bbox或父关系字段。视觉text和input是只读候选，未知/重复身份、漏槽和额外字段拒绝。代码用既有唯一标签/原文/行为校验落实text→input；已是原生input时记绑定确认，不伪报类型改进。绑定未知或歧义标未决，不补节点。模型选择错误仍可能发生，须审核所有映射和未决。

两组共享本轮新视觉、架构2次；候选额外至多一次需求绑定（非关系取证），整轮最多3物理调用，有效基线2/候选3，不能称同调用数消融。两组同原架构提示、来源/关系严格校验、container_extent_v1、受控组件生成；无Coder、无关系专门调用。与轮22独立采样，不能作跨轮因果提升。每阶段8192token/600秒/零重试，原模型不变。

主目标：明确文字输入原文槽得到合法唯一绑定或显式未决，漏槽0、模型编写新引文0，并且主聊天输入实测1/1，候选生成页面；须同时报告绑定数/原文槽数、未决和真实类型变更数。如果基线也1/1且没变更，不称用户输入提升。slot分母0不可评；这是规则覆盖的编辑句子，不是全部口述需求召回率。要求七标签相关提示不下降、PC1440×900、结构尺寸全部落实、0越界、对象唯一、原位置/文字/父关系/节点数不变；全部原遮挡、消息头像/分栏遗漏仍报告，不称完整可用。无HTML则候选DOM指标不可评。冻结12ER/12TR/21SR/8AS不改。
