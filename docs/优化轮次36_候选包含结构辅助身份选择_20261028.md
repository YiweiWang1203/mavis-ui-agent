# 轮36：候选包含结构辅助身份选择

1. 用户任务：在已能产生整页外框的情况下，自动选出整页而非左栏、输入框或主聊天区。轮35仅证明开发例候选存在1/1，实际选择未评，局部候选11个。
2. 定位：原选择器主要接收图像、候选编号和独立面积/支持信息，没有各候选之间的包含结构。轮32要求模型额外输出完整assessments，被忽略而失败；本轮不继续叠必须输出字段，不改JSON契约，也不依赖供应商未核验的严格schema能力。
3. 目标后复读《手绘页面定位与空间理解_学术路线复核》Magic Layouts的UI结构先验及Sketch2Code对草图理解仍不稳定的反证。候选间包含关系作为辅助证据是本项目工程设计，不是两文算法复现，不宣称几何包含就是页面身份。独立导师SKILL未找到，遵循user-centered-optimization。
4. 假设：将代码计算的候选包含关系作为只读上下文提供给同一次选择调用，可帮助辨别“完整页面—内部区域”，减少局部框误选；仍须根据原图和口述区分纸张与UI。
5. 固定方案：冻结35全部几何生成函数。同一新LSD/48锚点/有界两跳生成一次候选，两组共享同一候选和接触图。为避免总是排第一的排序提示，两组统一按候选几何SHA256顺序重排、重新编号，保存旧新映射，不按正确答案选排列。基线原ID选择；候选仅增加代码计算的包含上下文和说明。凸四边形交集由几何裁切计算；较大框面积比>=1.05且覆盖小框>=95%时记可能容器，阈值固定，仅减少上下文大小，不裁掉候选、不改变任一坐标或接受规则。纸张也可能包含UI，不能自动选最大框。两组均只输出candidate_id/unresolved_reason，允许未决，严格旧ID校验，原始输出完整保存。
6. 指标与预算：两组实际正确整页选择各按1例报告分子分母；内部/纸桌误选与未决、schema/API失败分开报。先确认本轮真候选仍存在，再审被选框及内容裁失；正确候选若缺失不得让模型造框。上下文为自算几何，不能当语义GT。两组各最多一次Qwen/Qwen3-VL-8B-Instruct，8192输出/600秒/零自动重试，总最多2物理调用，0深网/无安装/原UV，新增输入token成本单报，不称完全同token预算。相同新几何和同候选排序可以隔离此上下文包，但同页一次选择不能称稳定泛化。两组都选对则不能声称上下文提高正确率；候选错选/未决/格式失败如实失败，不重试挑优。无HTML/功能分，无GT/旧HTML修补/ASR选帧重跑，13例仍开发，实施者目检非独立人工。先完成本关，之后才能画布映射与区域规划。
