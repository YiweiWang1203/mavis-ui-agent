# Ubuntu同步与真实重生成验证

本轮只验证真实生成链路，不修复已保存HTML。候选分支codex/native-input-generation。原项目仍保留，独立检出目录复用原项目.venv和.env，原始案例只读。

在Ubuntu终端执行以下命令（不要复制终端提示符）：

```bash
(
set -e
project=/wyw/meeting_agent_workspace/my_agent
checkout=/wyw/meeting_agent_workspace/my_agent_native_inputs_v1
cd "$project"
git fetch origin refs/heads/codex/native-input-generation
revision=$(git rev-parse FETCH_HEAD)
git worktree add --detach "$checkout" "$revision"
cd "$checkout"
git rev-parse --short HEAD
"$project/.venv/bin/python" -m unittest discover -s tests -p test_generation_contract.py -v
"$project/.venv/bin/python" scripts/start_native_input_validation.py --project "$project" --dry-run
"$project/.venv/bin/python" -u scripts/start_native_input_validation.py --project "$project"
)
```

`git worktree add`若目录已存在会停止，不清理或覆盖。检查后使用新目录或进入已存在目录核对提交；不要强制覆盖原项目。set -e仅让本段前置失败即停止；批处理中单组模型失败会记录并继续另一组。

脚本在原项目outputs/pilot_cases寻找唯一002_chat_asr_v1、003_asr_*、008_asr_*。若同编号匹配多个会在任何模型调用前停止，列明匹配规则；改用run_generation_comparison.py --cases传入明确的三个案例目录，不自动挑选最好或最新结果。

每例两组都是新的视觉→架构→Coder请求，每阶段8192输出token、600秒、无自动重试。3例最多18个模型请求（不是18个页面），共6个新页面，可能需要较长时间。只有Coder提示约束不同，第一例原版先跑、第二例候选先跑、第三例原版先跑。一次运行只作开发方向验证；后续正式实验需重复和更多案例。

输出位于原项目outputs/optimization_generation/时间戳/，独立保存每组call_*.json、ui_state.json、coder_response.txt、final_code.html、run_summary.json与batch.json。末尾打印Evidence ZIP路径，可沿用scp下载。归档只含本批案例输入与调用证据，不包含.env。若是API准入或连接故障，先检查原有凭据和模型访问，不安装依赖或下载模型。
