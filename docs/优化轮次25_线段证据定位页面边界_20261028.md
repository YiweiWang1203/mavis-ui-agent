# 轮25：先核验手绘页面边界（边界子实验）

1. 用户失败：24轮把整照片当手绘页，后续区域定位无参照。用户提出线、分割线、线框可能被忽略。源码核查：vision_schema已有divider，ui_element_ontology另有shape=line/rectangle；不能说系统完全没有线概念。但当前输出没有通用线段端点/闭合侧边来源，SketchRectifier只是最大四边形，不确认手绘UI还是纸。不是把所有框都当divider；几何笔画和语义控件分层保存。
2. 原因：24轮同时定位页面/区域/11控件，页面边界未成功，不能再堆区域字段。本轮只查外框，不生成HTML、不评交互或声称完整系统改善。
3. 假设：先用已有OpenCV提取可观测直线段，模型仅选择四条已有侧边ID、代码算交点与覆盖，比自由报bbox更可能定位实际手绘外框；模型可返回未决，不能回退整照片。不是解决全部线语义、不是闭合检测万能方案；手绘曲线、缺边、低对比可能失败。
4. 目标之后复读既有证据几何/布局几何分离调研，查官方OpenCV LineSegmentDetector说明 https://docs.opencv.org/4.10.0/db/d73/classcv_1_1LineSegmentDetector.html 。采用现有cv2 LSD默认参数，保留长度≥图像短边12%、近横/竖20度内的段，每方向最多24，近中心5px去重。阈值是固定工程启发，不为002手工画坐标，不装新模型。MM-WebAgent只提供全局先于局部的职责依据，不声称其使用此算法。

5. 对照：同一冻结002帧、同一口述/模型；direct_boundary一次原图自由bbox，line_supported_boundary一次同原图+带ID叠图+检测段清单选择四侧ID。两组每组1、整轮最多2物理调用，8192/600秒/零重试，不取证/输入绑定/Coder。调用数相同但候选视觉内容和token更多，另报，非同提示消融。不读旧响应或HTML、不用GT、无ASR选帧重跑。

主验收是当前原图上实际手绘UI外框1/1，四条所选边是否对应真实手绘页而非纸/桌纹、四角是否合理、主要内容是否保留；同一实施者视觉审查，不伪造独立标注或IoU真值。线段引用必须存在、4不同ID，交点图内/凸四边形/顺序正确，面积≥照片2%、每侧段长至少推定侧长35%；这些只是工程筛选，不自动等于语义定位正确。完全没候选须未决，不造线。输出原图叠框、1440×900映射草图供视觉检查；映射图是输入诊断不是新HTML，不能填浏览器交互得分。所有候选、原始调用、失败、映射和哈希保留。

6. 若边界子目标达成再集成到后续区域规划；若失败定位检测候选缺失/选边/交点/语义哪层，不自动重试、不把旧响应手改。仅002开发单例、独立导师SKILL未找到，遵循user-centered-optimization。工程测试不是准确率。冻结论文评分不改。
