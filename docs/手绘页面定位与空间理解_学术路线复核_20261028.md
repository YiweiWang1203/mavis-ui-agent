# 手绘页面定位与空间理解：学术路线复核

日期：2026-10-28。性质：针对当前失败的定向文献调查与技术建议，不是方法效果实验，也不是穷尽性综述。独立同名“导师”技能未找到；遵循 user-centered-optimization 六步流程。检索使用论文出版方、作者论文与官方仓库。Firecrawl部分搜索额度不足，改用网页检索；三个并行核验任务因额度限制未完成，因此本记录不能称独立复核。

## 1. 固定研究问题与当前事实

RQ1：如何表示、保留并连接页面的线与交点，避免有效短线在候选筛选前消失？

RQ2：如何区分实体纸张、纸内手绘UI页面、内部区域/控件框，并保持全局到局部的空间关系？

RQ3：哪些机制适合现有系统、小样本和有限预算，怎样判定值得接入？

轮29原图不变，LSD筛选后48条源线，聚合39组，其中17组多源。两组均无可用页面候选，实际0次LLM调用；不是模型选错了一个已有正确候选。当前 `src/utils/page_line_boundary.py` 在候选生成前按最短长度、近横竖角度、中点距离去重和每方向24条上限筛选。源码证实这些机制存在；尚未证实其中哪一项删掉了真实页面证据。不能把继续放宽角点延伸当成有依据的下一步。

## 2. 线和交点：借鉴联合结构，而非只搜更长线

### 2.1 L-CNN、HAWP：直接相关的表示方法

Yichao Zhou, Haozhi Qi, Yi Ma. **End-to-End Wireframe Parsing**. ICCV 2019。

[论文](https://openaccess.thecvf.com/content_ICCV_2019/papers/Zhou_End-to-End_Wireframe_Parsing_ICCV_2019_paper.pdf)，[作者代码](https://github.com/zhou13/lcnn)。将图像解析为线段与交点组成的矢量线框，并评价连接错误和线段重叠。可借鉴其表示和评价思想；原任务不是纸上手绘UI页面身份识别。

Nan Xue et al. **Holistically-Attracted Wireframe Parsing**. CVPR 2020；后续 **Holistically-Attracted Wireframe Parsing: From Supervised Learning to Self-Supervised Learning**，TPAMI 2023（官方仓库标注）。

[CVPR论文](https://openaccess.thecvf.com/content_CVPR_2020/html/Xue_Holistically-Attracted_Wireframe_Parsing_CVPR_2020_paper.html)，[官方代码及v2/v3](https://github.com/cherubicXN/hawp)。联合提出、匹配和验证线段与交点。官方有推理示例与权重入口，代码标为MIT；文档安装栈较旧，需隔离环境兼容核查，不能直接改项目UV环境。作者展示跨域图像例子不等于已验证我们的手绘UI。

**建议改造**：保留原线段、端点和置信度，建立“端点/交点—线段”的图，再评价四边候选；把实际观察到的线、推测连接和未知边分开记录。先用现有检测证据检查这套表示是否改善候选覆盖，再决定是否试HAWP。此处图建模是任务化设计建议，尚未实施，不冒称复现HAWP。

### 2.2 LETR：提醒我们检验人为筛选的代价

Yifan Xu, Weijian Xu, David Cheung, Zhuowen Tu. **Line Segment Detection Using Transformers Without Edges**. CVPR 2021。

[原论文](https://openaccess.thecvf.com/content/CVPR2021/html/Xu_Line_Segment_Detection_Using_Transformers_Without_Edges_CVPR_2021_paper.html)。直接预测线段端点，减少依赖中间边缘、交点提取等启发式步骤。它提供另一种检测路线，但不自动输出“这四条是UI外框”的语义判断。对我们的启示是先测已有筛选是否造成损失，不能据此直接宣称端到端模型一定更好。

### 2.3 ELSED：较低成本的检测器对照

Iago Suárez, José M. Buenaposada, Luis Baumela. **ELSED: Enhanced Line SEgment Drawing**. Pattern Recognition 127, 108619, 2022。

[论文DOI](https://doi.org/10.1016/j.patcog.2022.108619)，[官方代码](https://github.com/iago-suarez/ELSED)。官方提供C++/Python线段及分数输出，代码Apache-2.0；有长短线段示例。可作为经典LSD之外的工程对照。依赖OpenCV开发/编译环境，不把“无需学习权重”说成“零安装成本”。也不能把其检测/连接能力解释为允许任意补齐页面缺边。

DeepLSD（CVPR2023）和ScaleLSD（CVPR2025）仍是有价值的现代线检测候选，详既有补充文档；轮27已完成DeepLSD有效接入，当前没有证据说明再换检测器比先纠正证据筛选更有收益。

## 3. 页面和区域语义：必须用界面结构，而不只靠四边形

### 3.1 Magic Layouts：直接研究手绘UI的关键参考

Dipu Manandhar, Hailin Jin, John Collomosse. **Magic Layouts: Structural Prior for Component Detection in User Interface Designs**. CVPR 2021。

[作者预印本](https://arxiv.org/abs/2106.07615)，[出版方论文](https://openaccess.thecvf.com/content/CVPR2021/papers/Manandhar_Magic_Layouts_Structural_Prior_for_Component_Detection_in_User_Interface_CVPR_2021_paper.pdf)。学习移动UI组件的空间共现先验，并用于检测手绘UI与截图中的组件。本次直接核验摘要与发表信息；出版方全文抓取受限，不宣称逐节复现。未核实可直接运行的官方预训练包。

**可借鉴**：页面类型、区域和元素应联合约束，例如侧栏中的历史列表、主区中的消息与输入区；单个外观相似的框不能独立决定元素类型。

**不能直接套用**：论文的移动布局先验不是电脑聊天页先验。我们的“页面→区域→元素”显式层级和桌面比例方案属于待验证改造，并非该文已给出通用父子树。也不能硬编码“聊天页一定有固定宽度侧栏”，覆盖用户真实草图。

### 3.2 Sketch2Code：既可复用评测，也提供反面证据

Ryan Li, Yanzhe Zhang, Diyi Yang. **Sketch2Code: Evaluating Vision-Language Models for Interactive Web Design Prototyping**. NAACL 2025（预印本2024）。

[出版方论文](https://aclanthology.org/2025.naacl-long.198/)，[官方代码](https://github.com/SALT-NLP/Sketch2Code)。研究草图到网页及交互澄清，提供基准、实验和数据生成脚本。论文发现现有模型仍难准确理解草图和提出有效问题；不能因为增加Agent或对话轮数就预期稳定提高。

**可复用**：评测和合成草图生成工具可作为以后训练/压力测试的起点。对于低置信度页面边界，只提出具体歧义供用户确认，也是值得单独比较的产品方案。用户确认后的辅助流程必须与全自动结果分开统计。该论文没有替我们验证“纸内UI框自动定位”。

## 4. 纸张、视频和矫正：辅助证据，不能替代UI身份

**SAM 2: Segment Anything in Images and Videos**. 2024预印本，ICLR2025。

[论文](https://arxiv.org/abs/2408.00714)，[官方代码](https://github.com/facebookresearch/sam2)。提示式分割及视频传播可用于跟踪已选目标。我们可以研究在末尾完整展示附近建立纸面/页面候选，再检查邻近帧可见性；这是任务改造假设。掩码并不保证找到纸内的手绘UI框，跟踪也不能恢复从未出现的边，最后一帧也可能模糊、遮挡或已移开。

**DocScanner: Robust Document Image Rectification with Progressive Learning**，预印本2021，官方仓库记录IJCV2025接收。

[论文](https://arxiv.org/abs/2110.14968)，[官方代码](https://github.com/fh2019ustc/DocScanner)。借鉴文档前景与后续几何矫正分工。实体纸面是一个目标，纸内UI外框是另一个目标。纸边被照片截断时，不能宣称完整纸张已经找到。

MM-WebAgent的分层规划可继续作为全局区域到局部生成的架构参考，具体溯源见既有文档；不能将它引用为手绘外框检测证据。无需为了当前子问题一次安装SAM、HAWP、ELSED和另一个生成Agent。

## 5. 推荐路线及优先级

| 优先级 | 工作 | 依据与理由 | 能否直接复用 |
|---|---|---|---|
| P0 | 审计全量线→筛选→聚合→候选，定位首次证据损失 | 当前零候选发生在语义模型之前；换模型前先定位系统自身损失 | 现有埋点扩展；无需模型调用 |
| P1 | 线/交点图与有来源的边界候选 | L-CNN/HAWP的联合结构表示；避免仅靠最长四线 | 先借鉴表示，权重需要独立小试 |
| P2 | 页面候选的语义验证与页面—区域—元素结构 | Magic Layouts证明UI结构先验值得研究；纸、页面、控件框需分别命名 | 借鉴思想，桌面先验须自行验证 |
| P3 | 末尾候选帧比较、必要时传播验证 | SAM2提供视频分割工具；完整展示属于视频证据 | 有代码，目标定义和选帧规则需改造 |
| 备选 | 边界仍不确定时明确未决或请求一次确认 | Sketch2Code交互设定可参考，但论文也揭示提问不足 | 评测脚本/数据工具可复用，辅助与自动分开 |

建议总体链路：末尾优先的多个候选帧 → 纸面/背景候选 → 保留短线及交点证据 → 手绘页面候选和语义验证 → 透视映射到手机/电脑画布 → 区域划分 → 区域内元素定位。箭头是拟研究的职责安排，不是已证明每一步必需，更不是现在已跑通的系统。

特别反证：真实使用可能没有画闭合外框。不能把“每侧60%支持+四角闭合”设成所有用户草图都必须满足的事实。此时可允许明确报告的语义区域估计或用户确认；不能伪称观察到四条实线。手机/电脑指目标矩形画布，照片里的页面可能是透视四边形。

## 6. 下一轮怎样验证，避免继续主观调整

下一轮应先做P0，暂不同时改变检测器、选帧、候选阈值和语义提示。保存全量端点与每一步拒绝原因，检查页面侧边和角点支持首次消失的位置。人工边界只供评测，不供检测与候选生成；002已用于开发，不能宣称未见泛化。

随后固定一个机制，先在同一图、同一原线集合下配对比较，分别报告：候选中是否存在真实页面、最终是否选中页面、纸/桌/内部框误选数，以及未决数。候选存在但选错与根本无正确候选分开统计。用同一对照才能判断候选机制收益。

需要用户确认的页面四角标注之后，才能报告四角误差（按图像对角线归一化）、四边形IoU、UI内容裁失率。阈值必须在正式评分前固定；未确认GT时只报可复核定性现象。对缺框、断角、透视、纸桌近色、内部大框、末尾展示不完整分别建挑战样本，保留不调参的后续材料。最后再验区域错属、比例误差、跨区遮挡和原有交互指标。

不将候选数更多、工程测试通过、文献开源、页面外框正确分别偷换成生成HTML可用。已有13例是开发材料，最终结论仍需冻结方法后的新例验证。文献、代码可用性和本系统实测三者分开记录。
