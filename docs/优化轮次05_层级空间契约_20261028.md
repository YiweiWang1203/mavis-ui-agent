# 轮次05：来源与层级空间契约

实施前记录。上轮真实结果：基线16→32、16框越界；候选16→26、15框越界，Coder HTTP500。候选前两层能调用，故不能仅凭该错误宣布凭据过期；也不能将26个元素当作去重成功。

原因诊断：上轮候选架构将顶部控件坐标写到400以上，虽目标宽375，几何匹配保守拒绝是预期，继续放松阈值容易误合并。缺少稳定来源和父子关系的结构契约，不能靠调匹配阈值解决。本轮目标是在新生成中保留来源身份与区域归属，避免布局器将祖先和子元素排成同一行。

目标确定后复查MM-WebAgent全局区域/局部元素分层规划：https://microsoft.github.io/MM-WebAgent/ 及既有调研。借鉴层级分工，不声称复现论文。采用一项贯穿架构、布局与Coder的结构契约机制：架构明确vision_id、origin、parent_id；程序验证一对一来源、有效父节点和无环，视觉元素用原始归一化框映射目标画布；布局沿父子关系递归约束，维持全局坐标与原始相对位置。父子范围可包含，同级冲突单独报告，不能再全局挤成一行。Coder在同一坐标系落实关系；不给生成器评测答案。

开关UI_STRUCTURE_MODE=baseline或hierarchy_v1。候选提示明确正确容器包含，替代矛盾的全部框互斥约定；代码强制身份和层级规则，不是只改提示词。两组均保持source_alignment_v1、相同视觉/Coder基础配置、8192输出token/阶段、600秒、零自动重试。008一次基线与候选各3次调用，最多6次。与baseline比较的是完整结构契约机制，不能将收益单独归因于某句提示或布局某行代码。

验收：来源ID唯一且覆盖视觉对象、口述新增保留；原口述支持的五条包含关系（导航三个按钮、选址卡片现在/预约）分别检查结构声明和浏览器实际位置；登录条位于地图下方并保持横向形态；所有框在画布或已声明内容范围；重复与搜索输入另报告。候选若合同/接口失败直接保留失败，不能只挑成功结果。空间不足及同级遮挡必须显示约束问题，不默默挤成1像素。完整HTML、静态关系通过不代表用户可用性通过。13例为开发回归，本轮只做008探索。

本轮并非纯层级算法消融：身份约定、父子字段、布局及Coder坐标约定是联合契约。旧响应诊断仅定位，正式验证必须真实重新生成，原产物不改。
