# 轮61：先验证照片坐标观察，再接目标页面映射

状态：实施前固定；坐标源阶段隔离实验，不冒称端到端新页面效果。

1. 用户失败：用户要求手绘内容在1440×900电脑画布上保留页面—区域—元素关系。60在融合附图后仍主输入0/1；两组12对象同类型/文字/父关系/最终bbox，截图基本相同，没有需求恢复。两组均消息可辨区域0/2、双方头像正确呈现0/2（不是冻结ER/TR）；历史入口仍无反馈。原始图显示手绘整体位于照片下半部，视觉却把返回/搜索报在y=.12附近，输入在y=.70，说明部分bbox不忠于照片。目检是实施者判断，非GT/IoU。
2. 原因：先把406×720照片与1440×900目标分开是正确工程要求，但观察bbox本身的参考空间尚不可信。60原生架构还把目标bbox输出为不同数值，随后身份代码用视觉bbox×viewport覆盖；仅多看图未改变用户结果。不能用60的12对象相比59的8对象宣称改善，两轮视觉不同。附图开关不默认启用；不继续重采样或加角色字段。
3. 导师判断：idea-evaluator的data-refuted规则使“单独给融合附图就能恢复需求”的本轮假设不获支持；其源输入可访问性不等于完成语义任务。tech-paper-template检查1/3/4要求下一模块先对应可观测的坐标错域，不提前宣称区域映射有效。项目六步要求逐层定位。目标后复读系统设计§3/4观察/语义/布局分离、链路调研MM-WebAgent分工和WebVIA操作证据；是职责设计借鉴，不是论文复现。
4. 单机制：真实视觉提取入口新增显式可选photo_observation_v1输入职责模式；system/schema/模型/温度/编码图像不变，仅视觉user文本由原生成请求+目标尺寸+口述，改为代码读取的照片宽高及只描述可见对象的观察任务。目标1440×900保留在原始输入包与下游要求，不删除电脑画布规则；本轮候选视觉不承担最终网页设计。不得用规则手填节点、四角、标签答案。两臂各一次全新视觉，图像字节相同；不是历史响应重放，不改旧HTML。

验收：原图与两组所有bbox叠图逐个核对，不按输出节点数判断。固定六类位置锚：返回、搜索、个人头像、Agent侧头像/消息区域、用户侧头像/消息区域、主编辑框；逐类报告可见目标是否检出、bbox是否落在照片中对应笔画位置，缺失/歧义不跳过。六类仅开发诊断，非独立GT或冻结ER。全部额外对象、错型、合并、漏分与凭空对象另报。照片宽高字段正确本身不是通过，bbox忠实且没有已有正确对象损失才有定位收益；不能因观察不含用户口述而要求虚构不可见对象。
