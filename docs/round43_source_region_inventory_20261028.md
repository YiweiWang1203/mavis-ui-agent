## 六步优化卡

1. 用户失败：手机导航被页面框排除；当前重点是页面—区域—元素关系，而不是完美四边框。42错误框通过，单中心点不能定位遗漏发生在哪个区域。
2. 根因：已证实42原始响应只含整页点，不是后处理删区域。待检验：同时要求观察和完整区域枚举可能造成职责遗漏。
3. 假设：通过先从原口述列出有逐字引文的主要局部区域，再将固定清单逐槽定位到同一完整帧，得到更完整、可审核的区域范围；若仍合并为整页、漏导航或错误绑定，假设不获支持。
4. 固定方案：008同一历史完整原帧，仅180度旋转；冻结原FunASR，无重新选帧。基线一次调用同时输出原文区域及bbox；候选一次仅原文清单、一次仅按只读槽ID定位。两组原始口述/图相同，但候选增加一次请求，非同调用数消融。清单引文必须是原文唯一子串，代码保存偏移；槽ID唯一、逐槽binding完整，未知/缺失/重复拒绝；null保留未决，不能丢弃；不补造父节点，不给模型评测清单或GT。根页面仅作为证据父ID，不推断页面bbox/手机比例，不运行LSD，不生成HTML。

主验收：按原图/口述独立人工清点的008五个主要区域报告识别并正确定位数/5（顶栏、地图、登录、预约卡片、底部导航，仅此文档评估用，生成器不得读取）。候选目标5/5，导航单独1/1；整页冒充局部区域0；所有引文原文支持，槽/绑定完整率分别列分子分母；空槽不算覆盖。与同次新基线分别报告。区域重叠须审语义（包含/共享边界可以合理），不靠bbox数量/零未决称成功。另报非主要区域/误项/全部遗漏。不能在无HTML时给操作分或宣称页面提升。

退化与预算：同Qwen/Qwen3-VL-8B-Instruct，8192输出token/600秒/零重试，整轮最多3物理请求（基线1+候选2），0深网、0安装。文本清单不见候选ID/历史响应；定位请求不见基线输出。原图SHA d1e3e82369c511201eceb454a8a8d25fde016c9cda4296d4d3b7627869df7751。逐请求原图URL哈希、源图/口述哈希、清单及编译前后、所有失败、token/耗时保存。原实验、脏修改和冻结论文不改。

研究回看：复读链路诊断与Agent架构调研及手绘页面定位与空间理解_学术路线复核的区域部分。MM-WebAgent支持全局与局部职责划分；Magic Layouts提示UI结构先验价值但不是本机制复现；Sketch2Code提醒理解仍会失败。这里是任务化来源契约与职责拆分，不声称论文中的架构/模型被复现，也不主张已有创新性结论。

5. 实施验证：待代码/测试/提交/独立UV启动；原包、内部产物哈希和区域叠图手审后补实测。
6. 下一轮决定：若区域完整性改善，保留可选探针并接真实页面层级验证；若原文清单漏项先查语义解析，若清单正确定位错查视觉绑定，若两者正确页面仍混乱查画布/区域布局。不得再回到无界补框或重复采样挑优。
