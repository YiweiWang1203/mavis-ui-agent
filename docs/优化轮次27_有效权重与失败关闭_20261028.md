# 轮27：有效权重与失败关闭

1. 用户失败：无法获知真实UV运行情况，边界探查虽有结果包但其中学习检测器权重未加载，不能信任表面完成状态。轮26负结果及全部恢复保留。
2. 定位：父venv与system-site-packages并不等于继承项目venv；已用显式site附加解决。PyTorch受限反序列化拒绝官方MegaDepth权重OmegaConf metadata，旧代码未清空model。这个确定性接入错误先于线检测能力判定。
3. 假设：仅在官方权重经受限加载及strict参数匹配成功后允许推理，并持久记录环境/加载/前向次数，可得到可解释的有效检测对照；本轮主要是工程恢复，不自称方法创新。
4. 方案：先复读DeepLSD与现代边界溯源记录，核查官方实现f7d9d6258c0cd25d4f6eea882853565403d289be；参考PyTorch serialization官方文档 https://docs.pytorch.org/docs/2.14/notes/serialization.html 的weights_only与safe_globals。静态审查checkpoint的10个全局类型，仅白名单collections.defaultdict、内置list/dict/int、typing.Any及已安装OmegaConf的AnyNode/Metadata/ContainerMetadata/ListConfig/DictConfig，不动态导入pickle提供的任意名称，不用weights_only=False。已只读加载验证144个model条目，尚不算前向。
固定同一图/权重/官方代码/检测参数/纸面处理，0LLM、最多2次有效DeepLSD前向、CPU允许且如实报告、600秒、零重试，无下载/安装/ASR/选帧/HTML。与轮26无效输出不作性能比较。主验收加载成功且strict参数通过1/1、实际前向2/2、有状态可核对；任一加载失败所有DeepLSD组必须failed且0前向。另审四侧线段/4与纸面裁失/混入，计数不是召回，无GT不编IoU。纸面前置仍不可靠，此轮不能证明可靠纸面后的算法提升。
5. 实施：load_official_deeplsd仅在完整加载后返回model，失败清空；batch保存checkpoint_loaded、actual_forward_calls、runtime真实解释器/依赖路径/CUDA。两项工程测试检查加载失败不创建检测器、strict错配不返回。新目录单次执行launch_verified_line_probe，复用原权重与隔离依赖，不修改原UV。预定原始证据state/results.zip，启动后保存实际路径和PID。
