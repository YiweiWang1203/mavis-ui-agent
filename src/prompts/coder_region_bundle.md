Return a single JSON object with keys components, panels, css, js. Do not return a document or Markdown.

- components: exactly one object {leaf_id, tag, attrs, inner} per supplied element ID. The program owns all layout IDs and assembles tree nodes in the supplied order. Use a genuine HTML root tag for each leaf, for example input for an input, textarea for multiline editing, img for an image, and button for a button. Use {} for empty attrs and "" for empty inner. Void tags input and img require empty inner. For embedded SVG use a div or figure leaf with SVG inside.
- attrs: string values only, such as {"type":"button","class":"primary"}; boolean attributes use "". Follow the attribute rules below. The program adds its id and data-ui-id from leaf_id.
- inner: balanced HTML content, with all non-void tags closed. Follow the allowed tag lists and normal HTML nesting. No comments, declarations, script, style, document, table or template tags. Use &lt; for literal less-than signs. Preserve planned content and text. Make visual assets recognizable, including compact embedded SVG when useful. SVG resource IDs use the same namespace, for example icon--gradient with fill="url(#icon--gradient)".
- Repeated items are ordinary content, never layout nodes. For a hypothetical leaf results, use ids results--row-1 and results--row-2 if needed, or data-item-key attributes and delegated click handling on document.getElementById("results"). Namespace dynamic IDs the same way. Content IDs must be globally unique. No data-ui-* in authored markup.
- panels: zero or more {id,inner} objects for expressly needed auxiliary dialogs or overlays. Panel IDs use panel--NAME and descendants use panel--NAME--CHILD. Panels are emitted outside the layout tree. Use a closed native dialog or hide an overlay initially.
- For example, a dialog in panel--example can contain `<button id="panel--example--close" type="button">Close</button>`. With the dialog ID panel--example--dialog, put its behavior in the bundle's js field: `document.getElementById("panel--example--close").addEventListener("click", () => document.getElementById("panel--example--dialog").close());`.
- css: a stylesheet without style tags. Style visual appearance, component internals, and dimensions. Layout tree direction, nesting, order, grow and bottom slots are applied by the program. Do not reposition layout nodes or change their display participation. Region cross_align uses align-self only; omitted alignment stretches. If a non-stretched panel needs a definite local bottom, size that panel explicitly from the provided requirements. A bottom slot is local to its own column. Keep the page readable and avoid clipping or horizontal overflow.
- Use layout_style_targets in the request to address every program-owned region or leaf. A region is a program-generated div with exactly the listed identity and layout attributes plus inline style. It has no class, and component attrs cannot add one to a region. Use its listed selector for spacing, background or overflow. Use a class selector for a leaf or inner element only if your own component markup provides that class. Address a panel wrapper by its declared ID and inner panel elements by attributes you author.
- The fixed_css map lists declarations applied by the program with inline !important. Style properties outside that map as needed. Width and height are available where they are not fixed, but an explicit grow uses flex-basis:0% and distributes remaining main-axis space; a CSS width or height does not replace that distribution. Do not try to resize layout by overriding flex, align-self, or the bottom margin. Set styles on the actual region selector or on content you own according to which box needs the visual change.
- js: a script body without script tags or inline handlers. It runs after the DOM. Use document.getElementById(leaf_id) to reach each native control and add real event listeners. Implement each requested trigger, state change and observable result. Keep program-owned nodes and markers in place. Update only leaf content, control state and auxiliary panels. Preserve usable keyboard and input behavior. Use no external framework or service. The CSS and JS fields cannot contain literal opening or closing tags for their enclosing style or script block, even inside strings or comments. Use language-level escapes for such text if needed.
