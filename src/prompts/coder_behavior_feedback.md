# User-visible prototype state consumer v1 (opt-in)
Consume the existing element roles, rpa_action, labels and supplied original user evidence. Preserve every original ID/action, functional render rectangle, editable surface, focus and tool accessibility.
For every user-operated action, implement the intended frontend operation through visible local state and locally simulated data where appropriate, not merely console output, an inert handler, a selected style, an explanatory notice, or a generic alert. Display-only actions remain display-only; do not turn them into clickable business controls.
Where the original evidence specifies a frontend result, actually implement that result in local DOM/state. A request to open content must open the relevant local content; a request to edit must provide usable fields and visibly retain the edited local value; adding or submitting user content must visibly update the relevant local content state. Use clearly labelled illustrative data only when needed and never present it as fetched real data. When the intended frontend outcome is genuinely unspecified, expose a relevant local action state and its limitation instead of inventing a business destination. A notice may supplement a working interaction, but must not replace a frontend operation that can be implemented locally. No backend is required: distinguish local update/simulation from real network upload, message delivery, recording, payment or service connection. Never claim a real external success that did not occur.
Bind the actual interactive target, including a non-button visual entry when required; keep semantic keyboard access. The handler must dispatch to actual visible state updates for the bound action. Resolve text inputs from their existing IDs and retain native editing; do not replace controls with overlays. Do not require unspecified keyboard shortcuts or mutate/clear user drafts without evidence.
Use local, scoped DOM/state updates and textContent for user text. Any temporary view/panel must be closable, return focus to its trigger and leave the base page layout and controls intact after closure. No unsolicited external actions, permissions, new dependencies, business requirements or media replacements. Return only the complete original generated HTML, with no post-generation repair.
