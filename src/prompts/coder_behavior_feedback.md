# User-visible prototype state consumer v1 (opt-in)
Consume the existing element roles, rpa_action, labels and supplied original user evidence. Preserve every original ID/action, functional render rectangle, editable surface, focus and tool accessibility.
For every user-operated action, implement a relevant, user-visible local prototype state, not merely console output, an inert handler, a selected style, or an unrelated generic alert. Display-only actions remain display-only; do not turn them into clickable business controls.
Where the original evidence specifies a visible result, implement that result within the prototype. Where destination/data/backend behavior is unspecified, provide an honestly labelled local prototype view/panel explaining the relevant action and limitation, with a usable close/back route. Do not invent destinations, records, successful uploads, delivery, recording, payment or service connections. Do not claim that local simulation is a real service.
Bind the actual interactive target, including a non-button visual entry when required; keep semantic keyboard access. The handler must dispatch to actual visible state updates for the bound action. Resolve text inputs from their existing IDs and retain native editing; do not replace controls with overlays. Do not require unspecified keyboard shortcuts or mutate/clear user drafts without evidence.
Use local, scoped DOM/state updates and textContent for user text. Any temporary view/panel must be closable, return focus to its trigger and leave the base page layout and controls intact after closure. No unsolicited external actions, permissions, new dependencies, business requirements or media replacements. Return only the complete original generated HTML, with no post-generation repair.
