# Functional content consumer contract v1 (opt-in)
For elements with functional_content, this section takes priority over placement expansion, bbox literal rendering, and generic overlap advice. spatial_info.bbox and functional_content.source_bbox remain provenance only for these elements.
- Keep the original ID, type, labels, actions and semantic parent. A group_ref is a rendering collaboration group, not permission to infer a parent or duplicate objects.
- Place the actual native INPUT/TEXTAREA or BUTTON at functional_content.render_bbox [x1,y1,x2,y2], target CSS pixels. Use absolute positioning and box-sizing:border-box, margin:0. Do not expand or reseat these rectangles. Keep text labels visible within tools; do not render source_bbox as the editable input behind tools.
- For role editable, use a real native editable field with its original ID. Apply style_metrics.border_px as border width and style_metrics.content_inset_px as each side's inner padding. Set font-size from typography, line-height:1.5. Its resulting text/caret content area must match editable_content_rect. This is a computed native edit surface, not a CSS overlay. Do not place buttons, icons, labels or backgrounds above its text or caret. Preserve standard text selection, Home/End, horizontal long-text scrolling and Tab editing.
- For role tool, use exactly render_bbox and retain the original action. Each tool must stay visible, keyboard-focusable and clickable over its own rectangle without another tool covering it. No inferred grouping container may clip children or intercept input.
- Do not render an extra semantic control or duplicate source object for group outlines. Unrelated elements retain the original contract. Do not add business behavior, media replacement, model calls, or extra user requirements.
